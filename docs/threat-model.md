# Threat model (v0.7)

## Assets
A1 control of VMs and hosts · A2 portal credentials, sessions, MFA secrets · A3 agent identities and the internal CA ·
A4 key ring · A5 audit trail integrity · A6 inventory confidentiality · A7 availability of management ·
A8 (v0.7) restore points (copies of whole VMs, secrets included) and the credentials of backup repositories ·
A9 (v0.7) the agent code itself (self-update chain) and the code-signing key · A10 (v0.7) API tokens, SMTP and
webhook secrets.

## Trust boundaries
B1 browser ↔ gateway (untrusted network) · B2 agent ↔ gateway (untrusted network, possibly different domains) ·
B3 gateway process ↔ its data directory · B4 agent ↔ Hyper-V WMI (local) · B5 OS administrators of gateway/hosts
(**trusted**: they can read keys and control Hyper-V directly; HvPortal cannot defend against them) ·
B6 (v0.7) hosts ↔ backup repositories (SMB shares, NAS outside the domain; whoever can write there is outside
HvPortal's control) · B7 (v0.7) monitoring systems ↔ public API (bearer tokens) · B8 (v0.7) gateway → mail server and
webhook endpoints (outbound) · B9 (v0.7) agent service ↔ SYSTEM updater task on the same machine · B10 (v0.7) host OS ↔
guest file systems attached for file restore.

## STRIDE

| # | Threat | Mitigation | Residual risk |
|---|---|---|---|
| S1 | Credential stuffing / brute force on login | PBKDF2, blocklist, progressive delay per account+IP and per IP, rate limit, MFA for admins by default, suspicious-activity audit | distributed slow attacks on accounts without MFA → enforce MFA `All` where possible |
| S2 | Stolen session cookie | HttpOnly, Secure, SameSite=Strict, idle/absolute timeout, server-side revocation, re-auth for critical actions, browser sign-out after 15 + 3 minutes without user input (v0.8.0) | malware in the browser; for Microsoft accounts the re-auth is a typed code (intent, not identity, ADR-038), so a stolen cookie can also pass it |
| S3 | Rogue agent / impersonation of a host | one-time token + CSR, private CA, DB-bound certificates, revocation | a host administrator can steal that host's identity (trusted boundary B5) |
| S4 | Rogue gateway (MITM) toward agents | CA pinned at enrollment by fingerprint, custom root trust, hostname check | operator skipping fingerprint verification |
| T1 | Tampering with audit rows | HMAC chain verified on demand; external export | DB + key ring holder can rebuild the chain → export to SIEM/WORM storage |
| T2 | Tampering with jobs in transit | TLS; typed commands; agent validation | — |
| T3 | Path traversal / reparse point on data dirs, VHD/ISO paths | data dir refused if any component is a reparse point; private ACLs; **new VHDX only in the host default VHD folder with generated names; ISO only inside the host ISO library (gateway containment check + agent `GetFullPath` + no reparse point on any path component); expand only for disks attached to that VM** | a host administrator can place hostile files in the ISO library (trusted boundary B5) |
| R1 | User denies an action | audit with actor, auth methods, IP, correlation id, outcome | — |
| I1 | Inventory disclosure across tenants/teams | per-VM filtering, 404 for unauthorized, hub messages only to authorized users, ids-only payloads | timing side channels |
| I2 | Secrets in logs | no request body logging, no secrets in audit details, tokens shown once | operator copying tokens into tickets |
| I3 | Setup token theft | file ACL limited to admins/SYSTEM/service, 24 h, single use, rotated on restart | local admin compromise (B5) |
| D1 | Account lockout DoS | no hard lockout; account-wide counter never blocks | per-IP throttling can affect users behind the same NAT |
| D2 | Job flooding | per-VM locks, bounded concurrency, idempotency keys | dedicated per-user quotas (M2) |
| D3 | CPU exhaustion through text validation (a path pattern that backtracked exponentially: a long folder name followed by a refused character kept a request thread, an agent command or the browser tab busy for hours) | fixed in 0.6.0: the folder patterns of gateway, agent contract and web are written so that each character matches in one way only; tests feed long refused paths and require an immediate answer | review of every new pattern applied to client text |
| E1 | Horizontal escalation (other VMs) | scope evaluation at request and job time; disks/networks/groups features will validate every referenced resource | — |
| E2 | Vertical escalation via role management | anti-escalation rules (see security model), tests | — |
| E3 | Gateway compromise → host takeover | gateway has no host credentials (except remote hosts, see T13); agent only accepts typed operations; no arbitrary execution endpoint | attacker can still power off/on VMs the agent can manage |
| E4 | Group user escapes the limits of the group (ADR-024) | hosts, networks and storage are checked server-side at request and at execution; the VM location and the folder of a new disk are set by the gateway, never by the client; `existingNames` and switch lists are filtered; group file access is confined to the group's storage paths; only private switches can be created with a group permission | limits are enforced by the portal only (changes made in Hyper-V are not prevented); a group user with VM console access controls the guest, not the host |
| E8 | Templates used to read or delete files outside the template library, or to obtain disks one is not entitled to (ADR-028) | template paths never come from a client: library chosen by `hosts.manage`, folder derived from the template id, disk list from the agent; re-stamped at execution; agent and script accept only `<library>\<guid>[\disk.vhdx]`, no junctions; deletion removes only disk files directly inside that folder; templates listed only to `vm.create` / `templates.manage` on the host | a template holds whatever was on the source disks (secrets included): generalize and clean the guest before; no per-template permissions yet |
| T13 | Theft of remote-host credentials (management agents, ADR-022) | opt-in per host; password AES-256-GCM with the key ring, bound to the host id; write-only API, not audited; only `hosts.manage` (global) + recent re-auth can set it; sent only to the assigned management agent over mutual TLS; agent keeps it in memory (SecureString), never on disk, dropped on disconnect; inventory for unassigned hosts discarded; WinRM without disabled certificate checks | a holder of the gateway database **and** key ring (or of the management agent's memory) obtains host administrator passwords: use a dedicated host account, prefer the agent on the host, rotate the password when a gateway or management server is rebuilt |
| S5 | Rogue management agent reporting other hosts | each inventory accepted only for hosts assigned to the reporting agent; commands stamped with the target by the gateway | a compromised management server controls the hosts assigned to it |
| E4 | Command injection in WMI/PowerShell | WQL built only from GUIDs formatted by the agent; PowerShell only through one fixed script with a fixed command line, JSON on stdin, closed operation switch, typed named parameters, no `Invoke-Expression`/script blocks (unit test enforced), validation at API, job execution and agent; sanitizer for free-text reason | notes are free text passed as a typed `-Notes` value (never evaluated) |
| E6 | Console hijacking (ticket theft, cross-site WebSocket, lingering access) | one-time 30 s ticket bound to user+session+VM, sent in the first message (not in URLs), Origin required, SameSite cookie, permission/session re-check every 60 s, idle/absolute timeouts, input validation, audit open/close | a user who may open the console can type into the VM like at a physical keyboard: grant `vm.console` accordingly |
| E7 | Escalation through group membership/moves | access-change guard (ADR-015): gaining Allow or losing Deny via groups needs `roles.manage` + held permissions; tests | — |
| E5 | CSRF / clickjacking / XSS | anti-forgery token, Origin check, SameSite, CSP without inline scripts (style nonce per response only for component `<style>` elements), frame-ancestors none, React escaping | — |
| E9 | (v0.7) Malicious code pushed through the agent self-update (compromised gateway, compromised agent service, tampered package) (ADR-029) | the gateway only offers a package; the agent checks size and SHA-256; installation by a SYSTEM task the agent account may only run (descriptor `GRGX` for the service SID); the task copies the package to a SYSTEM/Administrators-only folder, requires the installed agent to be signed, the package catalog and the new `HvPortal.Agent.exe` signed by the **same thumbprint**, `Test-FileCatalog` valid for every file, no downgrade; unsigned builds never installed; `-DisableRemoteUpdate` removes the task; downloads and requests audited | the signing private key is a key to every agent (keep it on the build machine only); a self-signed signer is accepted by thumbprint with an untrusted root; the package is expanded as SYSTEM before its catalog is checked, but only after every zip entry was checked to be a plain relative path inside the extraction folder; a gateway compromise can still force reinstalls/upgrades to any signed, not older version |
| S6 | (v0.7) Stolen or guessed API token (ADR-032) | 40 random characters (≈ 233 bits), only SHA-256 stored, shown once; closed read-only scope `backup.read` on `/public/*` only; optional expiry; revocation; HTTPS; rate limit 120/min per address; refused tokens audited; creation needs `settings.manage` + re-authentication | a token reveals job and VM names and backup status of the whole portal (not RBAC-filtered); it stops when its creator is disabled or deleted but not when the creator loses `settings.manage`; no IP allow-list; refused attempts audited at most once per token prefix and minute |
| T14 | (v0.7) Theft of backup repository credentials (ADR-031) | AES-256-GCM with the key ring, purpose bound to the repository id; write-only API, never audited; not stored in job parameters (stamped at execution); sent only inside the command over mutual TLS; used as a process-scoped PowerShell drive, never written to disk by HvPortal | a holder of the gateway database **and** key ring obtains the NAS passwords; PowerShell module logging on a host or management server may record the value passed to `ConvertTo-SecureString -AsPlainText` / `Invoke-Command -ArgumentList` (to verify, V58); use a dedicated NAS account with rights on the backup share only |
| T15 | (v0.7) Tampering with restore points in the repository: planted or altered VM copies restored into production (ADR-031) | point folder and file names validated; a point is used only with a manifest whose point id matches; verify compares size and SHA-256 with the manifest; rescanned points are `Unverified` and attached to no VM (only Global holders restore them, only as a new VM, never *Replace*); restores need `backup.restore`; *Replace* only on the VM id recorded by the portal, with re-authentication | the manifest is **not signed**: whoever can write to the share can rewrite files and manifest of a point the portal knows consistently, and `Unverified` points can be restored. Restrict write access of the share to the backup account/host computer accounts; use storage-side snapshots or immutability for protection against ransomware (not provided by HvPortal) |
| I4 | (v0.7) Disclosure through restore points and file restore (ADR-031) | restore points readable only through the portal permissions; file browsing only by the user who attached the disk, `backup.restore` re-checked per call, only the volumes of that mount, no junctions followed, guest NTFS permissions apply to the agent account, downloads audited with SHA-256; disks detached after 2 h idle | a restore point contains everything the VM had (secrets included) and anyone with access to the share reads it directly; while attached, the volume is visible to the host's administrators and processes; the host chosen for a mount (`hostId`) is not checked against the caller's permissions on that host |
| T16 | (v0.7) Hostile guest file system attached to the host OS for file restore | read-only attach (`Mount-VHD -ReadOnly`), only drive-letter volumes, agent-owned mount list, idle detach | the host's file system drivers parse a disk written by the guest (a compromised guest can craft it): use file restore for trusted VMs, or restore the disk to an isolated VM instead |
| I5 | (v0.7) Secrets of notification channels (ADR-033) | SMTP password sealed with the key ring and write-only; webhook URLs returned masked; nothing sent until configured; `settings.manage` only | webhook URLs sealed with the key ring (readable by whoever holds database **and** key ring); SMTP without TLS refused when credentials are set; messages carry VM names and errors to external services |
| S7 | (v0.7) Server-side request forgery through webhooks | https only, no user info in the URL, POST of a fixed JSON body, response body never returned, 20 s timeout | loopback, link-local, unspecified and multicast destinations refused (literal and after DNS resolution, in the connect callback), no redirects; private (RFC 1918) destinations allowed on purpose: a `settings.manage` holder can make the gateway POST a fixed body to internal HTTPS services (blind) |
| E10 | (v0.7) Gateway or portal user reaching folders of a host outside its allowed storage folders (ADR-034) | the list is decided on the host and enforced by the agent on the real file system for every folder of a request; fail closed on an invalid configuration file; the browser cannot go above an allowed folder | default folders of the host are checked by the script against the list the agent passes with each request; the portal refuses to set the list for remote hosts whose management agent is older than 0.7.0; the agent account has full control of its data folder |
| E11 | (v0.7) Access changes through a VM move (ADR-035) | `vm.migrate` on the VM + `vm.create` on the destination, re-checked at execution; group limits on hosts and storage | host-scoped role assignments of the source stop applying and those of the destination start applying (Deny included) without the ADR-015 access-change guard |
| D4 | (v0.7) Long jobs starving the job runner (backups of many VMs, restores, moves) | separate concurrency budget for long jobs (`MaxConcurrentLongJobs`, default 4) besides `MaxConcurrentJobs`; agent time limit 12 h | the runner examines only the 50 oldest queued jobs per pass: a backlog of more than 50 queued long jobs can delay short jobs queued after them (to verify, V65); a backup holds the VM lock for its whole duration |
| R2 | (v0.7) Destructive restore (*Replace*) | typed VM name; only the VM the point was taken from, without checkpoints; old disks renamed `*.pre-restore-<time>`, never deleted; audited | importability checked with `Compare-VM` before the original is touched; re-authentication asked; if the import still fails the VM stays removed from Hyper-V (disks kept) |

## Out of scope / accepted
- Compromise of an OS administrator account on gateway or hosts.
- Physical attacks; Hyper-V vulnerabilities; side channels between VMs.
- Availability of the gateway beyond a single instance (SQLite; HA requires M2 server databases).
- (v0.7) Security of the backup storage itself (NAS hardening, share ACLs, encryption at rest, immutability, off-site
  copies) and application consistency inside guests: HvPortal copies VMs, it does not protect the repository or the
  applications.
